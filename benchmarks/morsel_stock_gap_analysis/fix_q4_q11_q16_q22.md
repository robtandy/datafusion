This report records the paired quiet-host SF=5 before/after benchmark results
and 22-query TPC-H non-regression verification for the root-cause fixes
identified by `#216` ([`q4_q11_q16_q22.md`](q4_q11_q16_q22.md)) and implemented
in `#219`.

## Implemented Root-Cause Fixes (`datafusion/core/src/morsel.rs` & `datafusion/core/src/morsel/`)

All five prioritized recommendations from `#216` (Ranks 1–5) were implemented
strictly inside `datafusion/core/src/morsel.rs` and `datafusion/core/src/morsel/`
with zero modifications to stock physical operators, `datafusion-datasource-parquet`,
`benchmarks/morsel_tpch/`, or DataFusion defaults:

1. **Widen `ensure_stage` Channel Capacity to `result_capacity(workers)` (`morsel/dag.rs`):**
   - Raised `ensure_stage`'s intermediate channel capacity from
     `stage_pipeline.sink_capacity.max(4)` (`= 4`) to
     `result_capacity(stage_pipeline.workers).max(stage_pipeline.sink_capacity).max(4)`
     (`= 16` at 8 workers, bounded by `MAX_RESULT_CAPACITY = 32`), eliminating
     8-worker backpressure during parallel 64-partition radix aggregate
     materialization on `q16` (`stage_0`), `q13`, and `q18`.
2. **Batch-Inlined Flat-Int `BuildSemi`/`BuildAnti` Probe + L2-Resident `RegisterBloom64` Prefilter + Cache-Line-Aligned NEON `SplitBlockBloomFilter` (`morsel/hash_join.rs`, `morsel/join_filter.rs`):**
   - Added `probe_mark_radix_flat_int` for `BuildSemi`/`BuildAnti` flat-integer
     and flat-integer-pair keys (`Int32`, `Int64`, `UInt32`, `UInt64`,
     `Int32Pair`, `Int64Pair`), eliminating per-row enum dispatch and duplicate
     `mix_u64` calls, and scanning `ProbeRows::Mask` via `BooleanBuffer::set_indices()`.
   - Added `RegisterBloom64`: a compact 1-word (64-bit) register-blocked
     L2-resident prefilter (max `65,536` `u64` words = `512 KiB`, `12 bits/key`,
     `k = 4` bits on disjoint `[16..40)` hash bits) built lock-free per Level-0
     radix partition during in-memory radix finalize (`num_rows <= 524,288`,
     pool-accounted via `try_grow`, skipped on spill) and probed with an 8-slot
     `aarch64` `prfm pldl1keep` ring buffer inside `probe_mark_radix_flat_int`
     (and checked inline in `probe_collect_radix_flat_int`). This cuts `q4`
     `morsel_no_pushdown` by `-121.1 ms` (`282.8 -> 161.7 ms`) and `q4`
     `morsel_pushdown` by `-32.6 ms` (`201.3 -> 168.7 ms`, `-254.9 ms` CPU).
   - Aligned `SplitBlockBloomFilter` blocks to 32 bytes (`BloomBlock`,
     `#[repr(C, align(32))]`), added NEON SIMD block checks on `aarch64` (with
     short-circuit scalar fallback on other targets), and added single-hash
     8-slot prefetching in `JoinBloomFilterExpr::evaluate` when the Bloom filter
     exceeds L1d cache (`> 32 KiB`).
3. **Concurrent Independent Small-Build Waves & 1-Worker Fast Path for 1-RG Builds (`morsel.rs`, `morsel/parquet.rs`):**
   - Grouped `run_build_pipelines` into topological dynamic-filter dependency
     waves. Within any wave containing stage-free builds where at least one is a
     small single-file Parquet build (`<= 8 MiB`, `<= 131,072` rows, e.g.,
     `q16`'s `supplier`), all small builds execute concurrently with at most one
     larger build in a shared `JoinSet` — preserving `tx.closed()` cancellation,
     `short_circuits_on_table`/`ShortCircuitAll` immediate peer abort,
     `DagRuntime` reference release, and zero spill contention between large
     builds.
   - Added `ParquetScan::effective_build_workers` so single-file 1-RG builds
     (`nation`, `supplier`, `region`) spawn 1 worker instead of 8, cutting
     `q16` `stage_0_build_1` `ready_wait` from `87.8 ms` to `1.2 ms` and `q11`
     4-build `ready_wait` from `25.0 ms` to `2.3 ms`.
4. **Compact-Span `DenseIntTable` (`ArrayMap`) Down to 1% Density (`morsel/hash_join.rs`):**
   - Extended single-table `DenseIntTable` eligibility to compact spans
     `<= 262,144` (`<= 1 MiB`) at `>= 1%` density (reserving any additional
     bytes via `reservation.try_grow` with soft fallback to `FlatIntTable` under
     tight memory pools). On `q11` `morsel_pushdown`, filtered German `supplier`
     (`2,003` rows over `[1..50,000]`, `4.0%` density, `200 KiB` L2-resident) now
     builds a direct `DenseIntTable` instead of falling back to `FlatIntTable`
     hashing.
5. **Scoped `BulkDecode` Policy Refinements for Small-Build, All-Predicate Radix, and Narrow-Payload Scans (`morsel/parquet.rs`):**
   - Active strictly when `AdaptiveRowFilterMode::Adaptive` is unoverridden:
     - **Dynamic small-build fixed-width scans (`q11` `partsupp`):** forces
       `BulkDecode` directly into `DenseIntTable`/`SingleHashTable` when there
       are no static predicates, all projected columns are fixed-width, build
       entries `<= 16,384`, and every dynamic filter has `sel > 2%` (too dense
       for `RowSelection` to skip pages; `q17`/`q20` `<= 5%` with static
       predicates or ultra-low selectivity remain in `skip_bulk_probe`
       `RowFilter`).
     - **Dynamic all-predicate radix scans (`q4` `lineitem`, `q22` `orders`):**
       forces `BulkDecode` + fused in-join `RegisterBloom64` when every
       projected column is fixed-width and already in the pushed predicates
       (`non_pred_payload_cols == 0`) and every dynamic filter is a flat-int
       Bloom filter in `(16,384..=524,288]`.
     - **Narrow-payload multi-column non-equality static scans (`q16` `part`):**
       forces `BulkDecode` when `>= 2` predicate columns contain no equality
       conjuncts (so `RowFilter` cannot short-circuit string columns) and
       non-predicate fixed-width payload is `< 25%` of projected row width
       (preserving `RowFilter` on `q17`/`q19` `part`).
   - Skips spawning unused Phase-2 I/O lanes and keeps `ready_capacity = read_ahead`
     when `ForceBulk` is selected.

  `8,192`, `--cache warm` (100% Linux `mincore` page residency verified before
  and after every trial).

  (`/home/bits/.cache/issue193/tpch_sf5`, 43,299,825 rows, 35 files, 353 row
  groups, Zstd level 3, `row_group_size = 131,072`).
- **Revisions compared:**
  - **Baseline (`BASE`):** `489bbc12e3651a7160f338472169449b44f4cfe3`
    (identical production Rust code to `morsel-execution` HEAD `326a7e5ac`;
    only tests and `fix_q14_q17_q20.md` changed between `489bbc12e` and
    `326a7e5ac`).
  - **Fixed (`AFTER`):** `aae746561eddd279cd9344668da87048678911de` (exact
    production code and tests of this PR).
- **Host idle checks (`vmstat -y 1 3`):**
  - Pre-run: `94–97%` idle; mid-run (between 4-query paired runs and 22-query
    paired runs): `99–100%` idle; post-run: `97–99%` idle. Every trial verified
    exact DuckDB 2.0.1 Arrow IPC parity before timing.
