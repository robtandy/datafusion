# Morsel Stock-Gap Fix Verification: TPC-H SF=5 `q14`, `q17`, and `q20` (#218)

This report records the paired quiet-host SF=5 before/after benchmark results
and 22-query TPC-H non-regression verification for the root-cause fixes
identified by `#215` ([`q14_q17_q20.md`](q14_q17_q20.md)) and implemented in
`#218`.

## Summary of Results (`morsel_pushdown` vs. `stock_pushdown`, SF=5 Warm Cache, 8 Threads)

All three target queries **eliminate 100% of the remaining Stock pushdown gap**
and **beat `stock_pushdown`** on both wall time and execution CPU with exact
DuckDB 2.0.1 parity and `morsel_mode = required`:

| Query | Baseline `morsel_pushdown` | **Fixed `morsel_pushdown`** | Before -> After Delta | Paired `stock_pushdown` | **Fixed `morsel_pushdown` vs. `stock_pushdown`** |
| ----- | -------------------------: | --------------------------: | --------------------: | ----------------------: | -----------------------------------------------: |
| `q14` |                 `306.8 ms` |              **`263.5 ms`** |  **`-43.3 ms` (`0.859x`)** |              `285.8 ms` |  **`-22.3 ms` (`0.922x`, `-21.1 ms` CPU)**       |
| `q17` |                 `478.1 ms` |              **`374.7 ms`** | **`-103.4 ms` (`0.784x`)** |              `447.3 ms` | **`-72.6 ms` (`0.838x`, `-252.2 ms` CPU)**       |
| `q20` |                 `311.4 ms` |              **`273.2 ms`** |  **`-38.2 ms` (`0.877x`)** |              `302.4 ms` |  **`-29.2 ms` (`0.903x`, `-87.5 ms` CPU)**       |
| **Sum (3Q)** | **`1,096.3 ms`** | **`911.4 ms`** | **`-184.9 ms` (`0.831x`)** | **`1,035.5 ms`** | **`-124.1 ms` (`0.880x`, `-360.8 ms` CPU)** |

Across all 22 TPC-H SF=5 queries (`morsel_pushdown`, 3 paired repeats, 22/22
exact DuckDB parity), total suite wall time dropped from **`8,797.6 ms` to
`8,282.1 ms` (`-515.5 ms`, `-5.9%`)** and total execution CPU dropped from
**`58,491.7 ms` to `56,941.6 ms` (`-1,550.1 ms`, `-2.7%`)**, with **20/22
queries faster** and zero regressions (`q6` `+1.2 ms` / `1.004x` and `q16`
`+1.8 ms` / `1.011x` within run-to-run noise).

## Implemented Root-Cause Fixes (`datafusion/core/src/morsel/` + Buffered Parquet Seams)

Recommendations #1–#6 from `#215` are active (Recommendation #4, lock-free
Level-0 radix-partitioned `SplitBlockBloomFilter` and unfiltered Bloom gating,
was already landed by `#217`), with zero changes to stock physical operators or
DataFusion defaults:

1. **Recognize `JoinBloomFilterExpr` as Infallible & Omit Redundant Dynamic Range Bounds in `RowFilter` (`row_filter.rs`, `push_decoder.rs`, `opener/mod.rs`, `opener/buffered.rs`, `morsel/parquet.rs`):**
   - Threaded `AdaptiveRowFilterContext`'s existing `ConjunctAnalyzer` into
     `prebuild_row_filter_candidates_with_grouping` (only when
     `group_same_column = true`; stock `FileStream` passes `None` and is
     unchanged) so `JoinBloomFilterExpr` fuses cleanly without triggering
     `DatafusionArrowPredicate::eval_staged`'s `filter_record_batch` copy and
     scalar bit-scatter loop over 60M rows on `q17`.
   - Added a `RowFilterSkipPredicate` seam on `AdaptiveRowFilterContext` that
     omits only redundant dynamic `[min, max]` bounds from row-level `RowFilter`
     evaluation when an accompanying single-column `JoinBloomFilterExpr`
     survives on the exact same Parquet leaf column — keeping `[min, max]`
     intact for row-group and page-index pruning, and strictly preserving all
     static user range predicates even on the same column.
2. **2x Two-Phase `RowFilter` Ready-Queue Capacity (`morsel/parquet.rs`):**
   - Sized `ready::channel` capacity to `min(read_ahead * 2, MAX_READ_AHEAD)`
     (`16` for 8 workers) for scans expected to run two-phase `RowFilter` I/O
     (`has_pushed_filter && (pushed_dynamic_filter || prefer_rf_wave1)`),
     eliminating Phase-1/Phase-2 semaphore starvation (`ready_wait` drops
     42–62% on `q14`, `q17`, `q20`) while keeping single-phase `BulkDecode`
     static scans (`q1`, `q6`, `q15`) at `read_ahead` to avoid L3 cache
     pressure.
3. **Parquet-Statistics Interval Selectivity in Build-Side Selection & Scoped Wave-1 `RowFilter` Policy (`morsel.rs`, `morsel/parquet.rs`, `opener/buffered.rs`):**
   - Added `ParquetScan::analyze_interval_selectivity`, partitioning conjuncts
     into interval-analyzable predicates (evaluated via
     `datafusion_physical_expr::analyze` over Parquet footer `column_statistics`
     min/max bounds) and remaining non-interval predicates (still handled by
     `pipeline_filter_shift`). On `q14`, `l_shipdate`'s 1-month window
     (`~1.19%`) flips the build side to filtered `lineitem` (`374K` rows, no
     strings) and pushes a dynamic filter onto `part` (`1M` rows).
   - Added scoped `AdaptiveRowFilterContext::with_prefer_rf_wave1` for
     single-column static scans with interval selectivity `<= 2%` and `>= 2`
     non-predicate payload columns (`q14`'s `lineitem` build), avoiding wave-1
     `BulkDecode` over-dispatch without regressing `q1`, `q6`, or `q15`.
4. **Transitive Equijoin Key Substitution Across `Inner`/`BuildSemi` (`morsel/parquet.rs`):**
   - Extended `remap_probe_key_to_scan` to substitute `JoinOutputCol::Build(b)`
     with `mid_probe.probe_key_exprs()[k]` across `Inner` and `BuildSemi` joins
     with `NullEquality::NullEqualsNothing` when the build column is a direct
     equijoin key of matching type (while continuing to reject `BuildOuter`,
     `FullOuter`, `BuildAnti`, and `NullEqualsNull`). On `q20`, this propagates
     `supplier`'s `s_suppkey` dynamic filter across `partsupp`'s `BuildSemi` and
     `GROUP BY` into `lineitem` (`stage_0`), increasing pushed dynamic filters
     from `12` to `15`.
5. **Higher L1-Resident Small-Build Bloom Density & Selective Dynamic `RowFilter` Fast Path (`morsel/join_filter.rs`, `morsel/hash_join.rs`, `morsel/parquet.rs`, `opener/buffered.rs`):**
   - Raised `SplitBlockBloomFilter::num_blocks_for_entries` density to 32
     bits/key up to 8,192 keys and 16 bits/key up to 16,384 keys (monotonically
     bounded `<= 32 KiB` L1d-resident), eliminating 96–99.8% of Bloom false
     positives on `q17` (`1,021` keys -> `4 KiB`) and `q20` (`2,028` keys ->
     `8 KiB`).
   - Added `AdaptiveRowFilterContext::with_skip_bulk_probe` when a scan carries
     a single-column integer/date dynamic Bloom/`InList` filter with `<= 5%`
     column-domain selectivity (`build_entries / col_span <= 0.05`) **and** at
     least one non-predicate payload column to skip (eliminating wasted
     `BulkDecode` probe RGs on `q17` `488/0` and `q20` `282/0`, while keeping
     A/B probing active on all-predicate scans like `q21`'s `l1`).
